## 1. C1 = 甲（四项精确化，权威表述）

**教室级免勤单元格写封顶值**：7614 = 111、7616 = 108。**绝不出现 112 > 111 的物理不可能值**（即使标了估算也不进上报口径）。

**超额 1 人不写入任何教室免勤单元格**，只在异常清单单列，并**定位到具体教室**——归属规则 = 比例分摊值 − 封顶值（7614：112−111 = 1；7616：108−108 = 0），故超额记在 **7614**。

**学院总免勤 220 不变**（原始声明保留，不封顶到 219），学院分母 = 219−220 = **−1** ⇒ 学院不出率；两教室分母 **0 / 0** ⇒ 均不出率（分母 = 0 亦属非正）。

**不变式**：`Σ(教室封顶值) + Σ超额 == 学院总免勤`（111+108+1 = 220），并追加断言「每间教室封顶值 ≤ 该教室应到」。**禁止**再把「Σ教室免勤 == 学院总免勤」当上报表断言。

**R1「禁截断」收窄为**：禁为凑出率而截断、禁丢弃超额、禁把分摊值重复累加；**允许**容量封顶 + 超额单列（对话口径授权）。

**异常清单该条目须一次写全**：学院、星期、自习、声明人数 220、学院应到 219、学院超额 1、分摊明细（7614：比例 112 / 封顶 111 / 超额 1；7616：比例 108 / 封顶 108 / 超额 0）、结论 = 学院与两教室均不出率、原因 = 分母非正。

**裁定依据**（对话全文 `_work/assistant_messages.txt:1444`、`:1515` 两处明文）：「程序保留原始声明，教室分配按容量封顶，另列 1 人超额；该组合的出勤率分母为负数，因此不生成出勤率。」

## 2. R11–R16 要点

- **R11 一层**：整型学号先左补零至该表实测学号众数长度（13）再进键空间，逐条留痕「整型学号已左补零」；12/14 位照常计入、标待核、**不得补零或截断**。**补零适用条件见 R20**（仅当补零后落在表内真实号段才作还原）。
- **R11 二层**：仅当两学号为**单字符插入/删除**（indel = 1）时视为同一人；**禁替换型合并**（改一位数字会把末位相邻的两个不同学生并成一人 ⇒ 少算免勤 ⇒ 率虚高）。合并只在同一 (星期, 自习) 上下文内生效，按 1 人计，两条原文进清单。实测：3 对不同学号对、6 个桶命中，**全为删除型，替换型 0 对**。
- **R12**：缺人数 ⇒ 免勤是**已知下界**，**照常计算**率（率是**上界**），但状态**强制**「免勤不完整（待补人数）」，界面与导出必须显示该状态，**不得以「完整」名义上报**；禁以 0 或推测值代替缺失人数；若下界分母已 ≤ 0 ⇒ 不出率。
- **R13**：「只取源表免勤时间字段、不推断、不默认」确认采纳；**R10 同一单元格内的段内配对属源串自带解析，不构成推断**；禁的是跨字段/跨行/跨表推断。源串缺失或不可解析 ⇒ 该行**挂起**（不计免勤、不进任何分母）并进清单，**挂起 ≠ 丢弃**。**★ 串班行按「免勤自习」字段归类，所在表只作异常标记、不参与归属**（早表 r178 字段=晚自习 ⇒ 归晚表侧；晚表 r2812 字段=早自习 ⇒ 归早表侧）。该规则的硬锚点：早表四天 = 160/163/158/163，与对话原文逐位吻合。
- **R14**：重建前逐列核对列标题，区间内**不得含非出勤率指标列**；晚表 R..T（值班辅导员未巡查次数，块 R4:T76）排除在范围外、整列合并不动；**早表 R 列经实证为平均列**（巡查次数在 S:U），故早表范围 N..R 成立。**禁硬编码 N..R / N..Q 常量**。
- **R15**：并列按**教室号数值升序**；教室号非数值时**不得**作 tie-break，改用该教室在明细表中的**行号升序**。规则写入词典/口径文档。
- **R16**：晚表差异须逐条归入六类之一——**容量封顶差 / 无明细列 / 全班无人数 / 全学期 / indel 合并 / tie-break 变更**；归因须落到行级（学院 × 星期 × 源行号 × 脱敏学号）；「口径修正导致的**预期差异**」与「**缺陷**」**分列**；**无归因的差异一律视为缺陷**。
- **段内配对 = 唯一周次×星期规则**：唯一实现为 `core.parsing.resolve_pairs(免勤周次, 免勤时间, 7)`（`core/parsing.py` 的 `_segment_facts()` + `_pairs_from_segments()` 七步）。**任何人工复算 / 对拍脚本必须调用同一函数，禁止另写解析器**；改用同一函数后混排写法的残差 = 0 ⇒ 此类残差归「口径变更（复算方法不同）」，不计缺陷。

## 3. Chief 新增裁定（R17–R21）+ 1517/1518 定案

**docgate 门定性**：`pytest.ini` 的 `addopts = -m "not docgate"` **成立**——**docgate = 发版前条件，不是每次构建条件**。打包闸门仍为 **255 passed + 8 deselected**；**发版前必须单独跑 `pytest tests -m docgate -q` 并 8/8 全绿**（已达成），且发布回执须**如实写明**「255 passed + 8 deselected（文档门，发版前单独执行 8/8 绿）」，**不得把 deselected 记作「全部通过」**。

**隐私扫描三个面**：源码树 / 产物二进制 / git 分支提交 + 完整 patch 历史；「被否口径旋钮」检查项的扫描范围**必须含 xlsx 单元格内容**（三个面统一逐单元格）；`.md` **不扫**（口径文档本身会写明「已否决」）。姓名比对按严重度分级：**与真实学号共现 ⇒ 高危**（阻断发布），**仅子串命中 ⇒ 低危**（单独成节供人工确认），避免误报训练大家无视闸门。

**显示层验收基线（v1.0.4，SL1–SL4）**：① 估算格斜体 + `FFFFF3CD` 一眼可辨；② 「免勤不完整（待补人数）」**不得**以「完整」名义出现，且整行须有视觉区分（复用既有 `row_colors`）；③ 缺失实到界面显示「—」+ tooltip「源表未填，待补录」，**导出保持真空白**；④ 晚表周五留痕行**必须与「出数」行视觉可分**。**界面改动不得改变任何上报数字**，合入前须**行为中性对拍**（免勤合计 120/120 一致、出勤率区 0 差异、合并区结构一致、屏风逐单元格 0 差异）+ 闸门全绿；可读性底线：正文对比 ≥ 4.5:1、控件边界 ≥ 3:1。

## 8. 隐私纪律

- 真实明细表、免勤表、统计结果、**真实文件指纹（含 md5/sha256）一律不进包、不进仓、不进文档**。
- 文档与代码内一律用仓库相对路径；禁出现任何本机盘符路径、用户名片段、Python 安装路径片段与 Linux/macOS 目录字面量（模式以 `tools/privacy_scan.py` 的 `PATH_PATTERNS` 为准，本文不列举字面量，避免扫描器自伤）。
- 学号、姓名一律用占位符（`<SID-xxxx>`、`<NAME-x>`、13 位假学号 99 号段）。
- 每次构建后重扫 `发布版/`，每次 push 前扫暂存区与提交 + patch 历史；**扫描未过 ⇒ 禁止打包发布与推送**。
- 界面与文档**不得出现真实学生的诊断、症状、姓名、班级**；随包只带类别与中性关键词。
