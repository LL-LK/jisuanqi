## 1. 审计背景与执行摘要

本地考勤工具（草莓小熊 / jisuanqi）主要用于高校“三早一晚”（早自习、晚自习）考勤明细数据统计、免勤名单核对与出勤率计算。为满足生产级日常使用要求，Milestone 1 针对系统既有业务逻辑进行了白盒代码审计与实测对拍，排查并修复了既有系统中的两处严重计算与流程逻辑缺陷，并从零构建了基于纯 Python 标准库 `sqlite3` 的本地历史数据库与 50MB/100批次双水位磁盘配额控制引擎。

### 核心审计与交付成果
1. **Bug 1 修复（单免勤表身份核验与核对表绕过）**：
   - 修正 `core/pipeline.py:126` 的硬编码判定，确保无论导入单份免勤表还是多份免勤表，均强制执行学院别名词典归一化、同学号跨学院身份冲突检测，并在存在待核对项时 100% 正常生成「免勤核对」工作表。

   - 修正 `core/calc.py:356-370` 的考勤分母口径，当学院存在部分教室未录入实到人数时，分母严格剔除缺失教室的基数，按有效教室的净应到人数计算，根除出勤率被异常拉低数十个百分点的统计口径失真缺陷。

## 3. Bug 1: 单免勤表身份核验旁路缺陷技术机理与修复

### 3.1 根因技术机理
在 `core/pipeline.py` 第 126 行：
```python
identity_check = result.college_exempt or len(exempt_paths) > 1
```
- **业务场景**：日常办公中最核心的场景是导入 1 份考勤明细表与 1 份免勤表（`len(exempt_paths) == 1`），且非汇总大表模式（`result.college_exempt == False`）。
- **连锁失真后果**：
  1. `identity_check` 恒为 `False`。
  2. 第 146~148 行的学院别名归一化循环 `record.college = _canonical_college(...)` 被跳过，脏文本别名（如“化生院”）无法标准化为“化学与生物工程学院”。
  3. 第 149~153 行传递 `identity_check=False` 至 `aggregate_exemptions`，导致核心函数 `_audit_personal_identities` 完全未被调用，跨学院冲突、同号异名冲突完全静默放行。
  4. 第 189~191 行向 `append_exempt_report` 传递空元组 `agg.anomalies if identity_check else ()`，导致 `core/exempt_report.py:161` 中的 `review_issues` 为空，生成的 Excel 工作簿中**绝对无法生成「免勤核对」工作表**。

### 3.2 修复方案
将判定条件修复为基于免勤表是否存在的真实布尔判断：
```python
identity_check = bool(result.college_exempt or exempt_paths)
```
- **修复效果**：单免勤表导入时 100% 触发学院归一化、跨学院与异名身份审计，并在存在需人工复核项时自动生成排版工整的「免勤核对」工作表。

## 4. Bug 2: 容错模式下有效教室考勤分母失真缺陷技术机理与修复

### 4.1 根因技术机理
在 `core/calc.py:356-370` 的容错计算分支中：
```python
valid_pairs = [(r, v) for r, v in zip(day_rooms, effective_values) if v is not None]
missing_rooms = [r for r, v in zip(day_rooms, effective_values) if v is None]
...
actual_sum = sum(v for _, v in valid_pairs)
rate = actual_sum / denominator  # denominator = 全院总应到 - 全院总免勤
```
- **数学失真本质**：分子 `actual_sum` 仅累加了录入实到的教室（有效教室），但分母 `denominator` 却使用了全院所有教室（包含未填实到的缺失教室）的总和。
- **业务危害**：相当于将未统计教室的所有在籍学生强制判定为“全部旷课旷自习”，人为大幅拉低出勤率。例如某学院 3 间教室各 100 人，前两间全到 200 人，第 3 间未统计，原逻辑算得出勤率为 $200 / 300 = 60.00\%$，而有效教室实际出勤率应为 $200 / 200 = 100.00\%$，失真幅度达 40%。

### 4.2 修复方案
1. 为 `Calculator.room_exemptions()` 增加 `_room_exemptions_cache` 结果缓存，保障分摊数据不重复计算。
2. 当存在缺失教室（`missing_rooms`）时，考勤分母动态调整为仅包含有效教室的考勤基数：
   $$\text{EffectiveDenominator} = \sum_{r \in \text{valid\_pairs}} \text{expected}_r - \sum_{r \in \text{valid\_pairs}} \text{room\_exempt}_r$$
3. 更新状态提示文案为清晰展示有效分子与有效分母的真实计算式：
   `按有效教室实到合计 X ÷ (有效教室应到 Y − 有效教室免勤 Z) 算得出勤率 ...`
4. 同步更新既有单元测试 `tests/test_dictionary_and_complete_calc.py:158` 的预期值为真值 `0.90`。

## 5. 本地数据库存储与磁盘配额控制架构 (F01-F05)

### 5.1 数据表关系模型
```
+------------------------------------------------------------+
|                         calc_runs                          |

|  attendance_rate, status)     |      |  day, actual, exempt, source) |
+-------------------------------+      +-------------------------------+
```

### 5.2 磁盘配额治理算法 (50MB / 100 批次)
每次调用 `AttendanceStorage.record_run()` 后自动执行 `cleanup_old_runs()` 四阶段治理：
1. **TTL 期限淘汰**：删除超过 180 天前的学期历史批次；
2. **FIFO 批次淘汰**：批次总数超过 100 批次时，按 ID 升序级联删除最旧批次；
3. **物理高低水位控制**：若数据库文件超过 50MB（高水位），循环淘汰最旧批次直至体积降至 35MB（低水位）以下；
4. **增量整理与 WAL 截断**：执行 `PRAGMA incremental_vacuum` 回收空闲页，在大量删除后执行 `VACUUM`，并执行 `PRAGMA wal_checkpoint(TRUNCATE)` 截断 WAL 缓存，保障磁盘空间 100% 物理释放。

### 5.3 防御性管道接入
在 `core/pipeline.py:run()` 结尾，成功生成 Excel 后调用存储 Hook：
- 写入前调用 `shutil.disk_usage()` 探测可用磁盘空间，低于 20MB 主动清理，低于 10MB 停止写入并预警。
- 整个存储操作使用防御性 `try-except` 包裹，若发生极端磁盘锁死或 IO 故障，仅在 `result.anomalies` 中记录警告，**绝不阻断核心 Excel 表格交付**。
