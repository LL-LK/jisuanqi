# 三早一晚考勤与免勤统计业务规则与白盒计算口径
# Attendance Statistics Business Rules & White-Box Calibers

## 1. 业务概述与核心指标定义 (Overview & Core Metrics)

“三早一晚”（早自习、晚自习）考勤与免勤自动统计系统负责高校本科生日常自习出勤核算、免勤人员分项冲抵、跨学院/校区数据归一化与防篡改对账。

### 1.1 核心指标定义

| 指标名称 | 英文字段 | 业务含义与数据来源 |
| :--- | :--- | :--- |
| **应到人数** | `expected` | 查课人员根据班级排课与自习教室安排记录的应出勤学生总人数。 |
| **实到人数** | `actual` | 查课人员在指定教室现场逐一核验的实际出勤学生人数。 |
| **免勤人数** | `exempt` | 经过教务、学工审批认可的正当请假人次（如课程冲突、就医病休、竞赛实训、公假等）。 |
| **出勤率** | `rate` | 实际到课人数相对有效应到基数（应到人数扣减正当免勤）的比值。 |

## 2. 出勤率数学模型与严格/宽容双模式 (Strict vs. Tolerant Modes)

系统在核心计算引擎（`core/calc.py:291-440`）中支持两种出勤率计算模式：**严格模式（Strict Mode）** 与 **宽容模式（Tolerant Mode）**。模式由运行配置 `--complete-mode {auto,strict,tolerant}` 或免勤词典「统计参数」中的「出勤率完整计算模式」（`'0'` 为严格，`'1'` 为宽容）控制。默认生产模式为 **严格契约模式（'0'）**。

### 2.1 每日 / 当次自习出勤率计算公式

#### A. 默认严格模式 (`complete_mode=False` / 词典参数 `'0'`)
严格遵循学术与管理审计契约：
$$\text{Denominator} = \text{Expected} - \text{Exempt}$$
$$\text{Rate} = \begin{cases}
\text{None (留空，显示为 —)}, & \text{若任何一个机房实到人数缺失 (None)} \\
\text{None (留空，显示为 —)}, & \text{若 } \text{Denominator} \le 0 \\
\frac{\text{Actual}}{\text{Denominator}}, & \text{若 } \text{Denominator} > 0
\end{cases}$$
- **关键口径修正**：在默认严格模式下，若分母 $\le 0$（即免勤人数达到或超过应到人数），系统**绝不**判定为 100.00%，而是输出 `rate = None`（界面与表格中留空，状态标注为「需人工核对」），防止异常免勤数据掩盖管理盲区。
- 若学院当天安排的若干教室中有任意一间未填报实到人数，严格模式下不折算，当天学院出勤率输出 `None`。

#### B. 宽容容错完整计算模式 (`complete_mode=True` / 词典参数 `'1'`)
面向数据不完全规整情况下的统计兜底：
1. **有效机房折算**：若学院所属部分机房实到缺失，仅基于实到有效的机房汇总 $\text{ValidActual}$ 与 $\text{ValidExpected}$，并扣减对应机房分摊的免勤 $\text{ValidExempt}$。
2. **分母 $\le 0$ 兜底**：当 $\text{Denominator} \le 0$（或 $\text{EffDenominator} \le 0$）时，出勤率按 **100.00%（满勤）** 计入：
   $$\text{Rate} = 1.0 \quad (100.00\%)$$
   并在说明中明确批注：`学院总应到 X − 当次总免勤 Y ≤ 0，按 100.00% 满勤出勤计入`。
3. 若实到人数超出有效应到人数（即 Rate > 100%），系统真实保留算得比率（如 102.50%），状态标记为「已计算（超过100%，需复核）」，触发 `OVERFLOW_EXEMPT` 或过量实到预警。

## 3. 每周综合出勤率 vs. 独立汇总终稿 (Weekly Average vs. Summary Workbook)

系统严格区分**明细表内的每周平均出勤率**与**独立汇总终稿工作簿**的计算公式（`core/calc.py:443-467` vs `core/pipeline.py:383-415`）：

### 3.1 明细表每周综合出勤率（算术平均值）
在结果明细表（`*_第N周计算结果.xlsx`）的学院出勤率列与每周出勤率汇总表中：
$$\text{WeeklyRate} = \frac{\sum_{d \in \text{ValidDays}} \text{Rate}_d}{|\text{ValidDays}|}$$
- 明细表中的每周出勤率是**该学院各有效排查日出勤率的算术平均值**。
- 若该学院在排查周内有应到日出勤率缺失（`rate = None`），则在说明中明确注明「已算天数/应统计天数」（例如 `3/4 天`），若没有有效天数则留空。

### 3.2 独立汇总终稿工作簿（总和除总和，恒走严格模式）
当使用 `--summary-out` 导出独立汇总终稿工作簿（`*_汇总终稿.xlsx`）时：
$$\text{SummaryWeeklyRate} = \frac{\sum_{\text{all days}} \text{Actual}}{\sum_{\text{all days}} (\text{Expected} - \text{Exempt})}$$
- **汇总终稿恒走严格模式**：
  1. 汇总终稿中各学院每周出勤率为**整周所有自习的实到人数总和除以有效应到人数总和**。
  2. 若该学院在整周内存在实到缺失、有效应到非正、占位学号待补人数、规则待核对或出勤率超过 100% 等情况，对应单元格留空并标记为 **「待复核」**。
  3. **v1.1.0 身份争议处理**：同号异名或同学号跨学院不再导致终稿出勤率留空，终稿照常计算并在「执行效果」列标注核对来源。

## 4. 机房免勤分摊算法与黄色高亮标示 (`ESTIMATE_RGB = 'FFFFF3CD'`)

### 4.1 最大余额法比例分摊 (Hare-Niemeyer Allocation)
当免勤表中的学生未明确填写具体抽查教室，或者属于全班级跨教室的集体免勤时，系统调用最大余额法（`core/calc.py:allocate`）：
1. 提取学院或班级在对应自习时段安排的所有教室及其当前剩余容量：
   $$\text{Weight}_i = \max(\text{Expected}_i - \text{DirectExempt}_i, 0)$$
2. 采用最大余额法（Largest Remainder Method）按权重 $\text{Weight}_i$ 确定性分配剩余免勤名额。
3. **容量上限硬约束（Capacity Cap）**：单一教室分配的免勤人数绝不能超出该教室的计划应到容量，且**严禁跨机房/跨教室二次溢出再分配**。超出总容量的部分作为 `exempt_overflow` 记录并触发审计预警。

### 4.2 黄色高亮标示 (`#FFFFF3CD`)
- 系统预定义颜色常量 `ESTIMATE_RGB = 'FFFFF3CD'`（浅琥珀黄底色，对应样式 `PatternFill` 与斜体字体 `Font(italic=True)`）。
- **口径澄清**：`#FFFFF3CD` 标记的是**按班级推断或按比例分摊的机房免勤人次（包含分摊后为 0 人次的单元格）**，用于人工审查免勤人数分摊分布。
- 它**绝非**“排课推断缺失机房”。`--match-classes` 参数默认为 `False`（未带教室号默认按已验收的比例分摊口径处理）。

## 5. 核心业务处理口径清单 (Core Business Calibers)

### 5.1 汇总模板输入模式 (`core/attendance_summary.py`)
- 当用户输入已包含各学院既有出勤率的汇总模板时，系统自动识别表头时段。
- 保留模板既有的出勤率数值，需提供至少 1 份免勤表，精准对账并回填早自习免勤、晚自习免勤与全周合计免勤人次，输出差异核对状态。

### 5.2 周次 × 星期 × 时段 `pairs` 约束与「全学期」语义
- 免勤时间解析器（`core/parsing.py` 与 `core/io_exempt.py`）将周次、星期与早晚自习组合成不可分割的三元时段对（`pairs: frozenset[(week, weekday)]`）。
- **「全学期」口径（裁定 R4）**：免勤表中出现的 `'全学期'`、`'本学期'`、`'整学期'`、`'一学期'` 等表述，一律精准覆盖当前计算窗口所在的活跃周次（默认第 7 周或 CLI 指定的 `--week`），确保学期长假或固定免修学生在每周自动纳入计算。

### 5.3 13 位学号左补零与占位学号挂起
- **左补零**：Excel 读取整数格式学号时常丢失前导 0，系统统一自动执行 `text.zfill(13)` 左侧补齐至 13 位标准学号。
- **占位学号与待补人数**：免勤表中若出现 `全班`、`全体`、`集体`、`无`、`待定`、`/` 等非数字占位符，且缺乏具体学生明细的，标记为 `免勤不完整（待补人数）`，作为 `warn` 级异常挂起并暂缓计入，要求院系辅导员补交完整名单。

### 5.4 多姓名与缺学号匹配及身份争议口径（v1.1.0）
- **缺学号对齐与拦截**：当免勤表仅有姓名、缺少 13 位学号时，引擎在当前学院及专业班级底册内进行模糊对齐；若仍缺少学号或存在多个可能身份（`学号无法核对`），暂不计入并写入「免勤核对」页。
- **同号异名 / 跨学院身份争议（v1.1.0 新口径）**：存在同学号跨学院或同一时段姓名冲突的记录，按 **`(学号, 星期, 自习)` 去重计 1 人，不再暂缓计入**；日出勤率与汇总终稿照常计算，并在「免勤核对」页列出所有来源表及行号，汇总终稿「执行效果」列标注核对来源，桌面端顶部固定提示条同步告警。

### 5.4.1 模板表头与合并区保留（v1.1.0）
- 导出保留明细模板原有的星期与平均列标题（兼容「平均」「周平均」及预留空白子表头），并保留首学院出勤率合并区（如 `N4:N8`），避免覆盖首个学院出勤率表头。

### 5.5 集体免勤覆盖个人免勤原则
- 当同一班级在同一天、同一自习时段同时存在集体申请（如“XX班全体学生共35人参加合唱排练”）与个别学生的个人病事假申请时：
  **集体免勤申请优先级高于个人申请，自动覆盖同班、同日、同时段的个人免勤**。
- 重复申请不重复扣减；不在集体申请当天的个人申请（例如该学生周一请假，集体申请为周三）仍然正常计入。

### 5.6 空白校区默认值映射 (`雁山` vs. `待确认`)
- 词典「统计参数」中包含配置项 `空白校区默认值`（默认为 `雁山`）。
- 历史考勤表中未填写校区的记录，默认归入雁山校区统计。
- 若教务管理员需要核查未填校区的数据，可将词典参数改为 `待确认`，此时所有校区为空的记录将全部挂起，不计入任何校区。

### 5.7 `屏风` 工作表零修改不变量 (Pingfeng Invariant)
- 无论明细表包含多少个校区或工作表，系统在导出结果时**严格只保留三张原始工作表：`雁山（早）`、`雁山（晚）` 与 `屏风`**。
- `屏风` 表（屏风校区）在处理过程中执行**逐单元格零改动（Zero Modification）**，原封不动保留原始公式、格式与数据。

### 5.8 运行环境 Python PATH 优先级
- 系统全流程强制依赖专用完整 Python 运行环境（包含 PySide6 与 openpyxl）。
- 本机若安装 LibreOffice、WPS 或其他集成办公套件，其自带的精简版 Python 可能抢占环境变量 PATH 导致缺失第三方依赖库。运行批处理与 CLI 脚本时必须显式指定项目专用 Python 解释器绝对路径，防范 PATH 污染。
